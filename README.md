# Лабораторная работа 5

Надёжность бизнес-логики: валидация, исключения и логирование.
6 академических часов. JDK 25, IntelliJ IDEA, Maven, JUnit 5.
Журнал — встроенный `java.util.logging`. Зависимости в pom.xml уже подготовлены.

## Задание

Выполните семь TODO:

1. `OrderValidator.validateId` — непустой id, иначе ValidationException.
2. `OrderValidator.validateAmount` — конечное число строго больше 0, иначе ValidationException.
3. `OrderService.createOrder` — валидация, защита от повторного id, создание CREATED-заказа.
4. `OrderService.findOrder` — валидация id и поиск существующего заказа.
5. `OrderService.payOrder` — оплата только CREATED-заказа, сумма оплаты точно равна сумме заказа.
6. `OrderService.cancelOrder` — отмена только CREATED-заказа.
7. `Application.runScenario` — выполнить action.run(), обработать два ожидаемых типа исключений.

В OrderService: успех создания/оплаты/отмены — INFO; успешный поиск — FINE;
отказ любой публичной операции — одна запись WARNING с причиной. После записи
WARNING исключение должно выйти из метода. В runScenario покажите пользователю
понятное сообщение и продолжите следующие сценарии; повторно логировать здесь не нужно.

Входные данные проверяются до бизнес-правил, все проверки — до изменения состояния.
Суммы double сравнивайте через Double.compare без округления. Частичная оплата не предусмотрена.
id сравниваются точно, без обрезания пробелов и изменения регистра.

Сообщение проверки id содержит `id`; проверки суммы — `amount` и переданное значение
(через Double.toString). Ошибка бизнес-операции содержит id заказа и причину.
Ошибка статуса содержит его имя (PAID или CANCELLED); несоответствие оплаты — обе суммы.
Точные формулировки свободные. Сообщения должны быть непустыми и информативными.

## Работа в IntelliJ IDEA

1. По ссылке преподавателя: **Get from VCS** или **File → New → Project from Version Control**,
   вставьте URL и нажмите **Clone**. Для архива: распакуйте, **File → Open** → папка с pom.xml.
2. **File → Project Structure → Project** → JDK 25. Дождитесь Maven-импорта;
   при запросе нажмите **Load Maven Changes**.
3. Меняйте только TODO в OrderValidator, OrderService и Application.runScenario.
   Готовые модели, исключения, LoggingSetup, pom.xml и тесты сохраняются.
4. Запускайте тесты зелёным треугольником у класса; все тесты — правый клик по
   **src/test/java** → **Run** для тестов папки. После выполнения должны пройти **49 тестов**.
5. Запустите **Application.main** зелёным треугольником. Итоги: O01 — PAID;
   O02 — CANCELLED; заказов — 2. Ожидаемые ошибки должны быть показаны без остановки сценариев.
6. Сохраните результат через **Commit**, затем **Git → Push** в свой публичный репозиторий.
   Для архива сначала **VCS → Enable Version Control Integration → Git**; первый коммит включает
   pom.xml, src, README.md и .gitignore. Адрес задаётся в **Git → Manage Remotes**.
7. Покажите преподавателю код, зелёные тесты, выполнение сценариев, уровни журнала и коммит на сайте.

В заготовке тесты, вызывающие TODO, не проходят — это ожидаемо. Скелет компилируется.
Подробные правила и примеры — в методических указаниях к ЛР 5.
